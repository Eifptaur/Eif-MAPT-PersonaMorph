[丙-14 窗口拉起耗时分段（任务 B，仅测量未改码）]

测量法：独立进程跑壳，time.perf_counter 分段打点；生产线程环境复用 start_qt_shell
复现（主线程忙碌模拟机器人循环）。全部跑壳均为后端离线（Qt 壳不依赖后端即可渲染）。

=== 独立进程（3 次取样）===
段                              耗时            备注
------------------------------  --------------  ------------------------------
import PySide6 + shell 全家     167 ~ 175 ms
Shell.__init__                  75 ~ 148 ms     27 面板惰性框架 + 托盘 + 壁纸
show() → 首帧                   ~585 ms        Qt 侧最大单段（首帧布局+壁纸解码+字体）
进程起 → 首帧                   871 ~ 893 ms
首次探活 HTTP                    2022 ms        异步（300ms 定时器），不阻塞首帧；后端离线才出现

=== 生产线程环境（主线程忙碌模拟机器人，4 次）===
进程起 → 首帧                   1565 ~ 1764 ms
（主线程 CPU 忙碌会拖慢 Qt 子线程首帧，故比独立进程慢约 0.7s）

=== 生产旁证（07:22 真实一键启动日志）===
persona_morph 启动 →「原生界面已打开」≈ 1.4s
⇒ 作者感知「1~2 秒」与此吻合。

=== 优化建议（等总监裁，均未动手）===
1. show→首帧 585ms：壁纸解码 / 非首屏构建后移，先出一帧纯色底；
2. 感知大头在 start_qt_shell 之前的启动序列——
   Qt 壳不依赖后端即可渲染（本次全部跑壳后端离线），可评估把 start_qt_shell
   派发提前到微信接入之前，窗口能早 0.5~1s 出来；
3. 探活 2s 超时与启动速度无关，仅需给离线告警限频（stderr 噪音治理）；
4. PySide6 import ~170ms 空间已小（qt_bootstrap 已热装秒回），优先级最低。
