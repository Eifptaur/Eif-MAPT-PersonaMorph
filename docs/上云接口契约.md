# 上云接口契约（给接收端的人看）

> 用途：群相（Persona Morph）控制台里的「上云」预留接口。
> **默认关**：总开关 `cloud.enabled=false` 时，本程序**一个字节都不会上传**。
> 这份文档就是"你要提供一个什么样的接口"的全部要求——照着做，我们这边填上网址即可对接。

## 一、接收端要提供什么

| 项 | 要求 |
|---|---|
| 协议 | `https://`（推荐）或 `http://`；**必须公网可达**（内网地址默认被我们拒绝，除非本机显式打开 `cloud.allow_private`） |
| 路径 | 你定，例如 `https://你的域名/hook/persona`、`…/hook/blocklist` |
| 方法 | **POST**，`Content-Type: application/json; charset=utf-8` |
| 鉴权 | 可选。要鉴权就要求 `Authorization: Bearer <token>`，把 token 给我们，我们填在控制台（只存本机、界面打码） |
| 请求头 | 我们会带 `user-agent: PersonaMorph/1.0` |
| 超时 | 我们默认 8 秒（可在配置里改 `cloud.timeout_ms`） |
| 成功判据 | **HTTP 2xx** 即算成功；非 2xx / 超时 / 连不上，我们只在本机记日志，**不会重试轰炸你** |
| 幂等 | 建议按 `client_id` 做 upsert（同一个人设反复上传不该产生多条） |

**连通性探测**：控制台的「测试连通」按钮只会发一个 **`HEAD`** 请求，**不带 Token、不带任何数据**。
你的服务对 `HEAD` 返回 405/404 也没关系——我们只借此判断"域名能不能解析、端口通不通、TLS 正不正常"。

## 二、我们发什么（请求体）

### 1. 人设（`cloud.persona_url`）

```json
{
  "kind": "persona",
  "client_id": "本机随机标识（同一台机器固定，用于幂等）",
  "updated_at": 1789315193574,
  "version": 1,
  "persona": {
    "bot_name": "群deepseek",
    "self_nickname": "",
    "participation": "medium",
    "role_text": "……人设正文（可能较长）……",
    "custom_rules": "额外规则",
    "sticker_level": 0
  }
}
```

### 2. 屏蔽名单（`cloud.blocklist_url`）

```json
{
  "kind": "blocklist",
  "client_id": "同上",
  "updated_at": 1789315193574,
  "version": 1,
  "blocklist": {
    "按群屏蔽的人": { "某群名": ["昵称A", "wxid_b"] },
    "屏蔽存档的会话": ["某广告群"]
  }
}
```

> 这两个结构**已经定稿**（和你本地存档的字段一一对应）；接收端只要收下并回 2xx 即可。

## 三、三种"传不过去"怎么判断

控制台「测试连通」会把**卡在哪一段**直接显示出来：

| 显示的段 | 含义 | 常见原因 / 对策 |
|---|---|---|
| `dns` | 域名解析不了 | 网址写错；或本机 DNS 被限制。先 `ping 域名` 看解析 |
| `tcp` | 解析到了但连不上端口 | **被墙 / 防火墙挡 / 对方没起服务**。对策：换公网端口、开防火墙、或走隧道（cloudflared / ngrok / frp） |
| `tls` | TCP 通了但 TLS 握手失败 | 证书不匹配/自签名/中间人。对策：用受信证书（Let's Encrypt），别用自签 |
| `http` | 连上了但没给出 HTTP 应答 / 返回非 2xx | 路径不对、只收 POST、或服务出错 |

**关于"被墙"**：本机实测 github.com / raw.githubusercontent.com 直连是**通的**（Python 侧 HEAD 成功）；
如果对方的服务器在国内直连不通，可选：①对方换国内可解析的域名/端口 ②走隧道拿到公网地址 ③我们这边配代理后重试
（当前**没有代理配置项**，需要的话加上 `cloud.proxy`，这是已知缺口）。

**关于"需要对方跑个程序"**：是的，必须有个 HTTP 接收端。最小实现（Python，10 行）：

```python
from http.server import BaseHTTPRequestHandler, HTTPServer
import json
class H(BaseHTTPRequestHandler):
    def do_HEAD(self):              # 只给"测试连通"用
        self.send_response(200); self.end_headers()
    def do_POST(self):
        n = int(self.headers.get("content-length") or 0)
        data = json.loads(self.rfile.read(n) or b"{}")
        open("received.jsonl", "a", encoding="utf-8").write(json.dumps(data, ensure_ascii=False) + "\n")
        self.send_response(200); self.end_headers(); self.wfile.write(b'{"ok":true}')
HTTPServer(("0.0.0.0", 8080), H).serve_forever()
```

（生产环境请加 HTTPS 与 Token 校验；上面只是让对方先"收得到"。）

## 四、我们这边的状态

- 总开关：**默认关**（`cloud.enabled=false`）⇒ 现在**不会上传任何数据**。
- 控制台位置：「社区与学习」面板 →「上云（预留）」：两个网址输入 + Token + 每行「测试连通」+ 连通结果。
- 接口层实现：`agent/cloud.py`（`normalize_url` / `probe` / `upload` / `snapshot`），HTTP 接口 `POST /api/cloud/test`。
- **等接收端定了再打开总开关**；在此之前 `upload()` 一律拒绝且不发请求（判据里盯着这一条）。
