# 跨机兼容性测试 · 交接包

> 用途：等**三个项目都做完**之后，把这份东西 + 测试包发到另一台电脑，让那台机器上的 Agent 帮我测，并把报告发回来。
> 状态（2026-09-15）：**测试资产已就位，等产品做完再发**。资产＝`scripts/collect_report.py`（随包检验工具）· `_scratch/兼容性矩阵.md`（13 条兼容轴）· `_outbox/兼容性矩阵-跑器-r3.zip`（跑器）。报告样例见 `报告/检验报告-20260913-164603.{txt,json}`。

---

## 0. 怎么用这份东西（三步）

1. **发**：把「测试包」（见 §4）通过微信/网盘发给另一台电脑；
2. **贴**：把 §1 的**开场白**整段复制给那台电脑上的 Agent（它是给 Agent 读的，不是给人读的）；
3. **收**：按 §3 收报告——`检验报告-*.txt/.json` + 一份 `结论.md`。

## 1. 开场白（整段复制给那台电脑上的 Agent）

```
你在这台 Windows 电脑上帮我做一次「跨机兼容性测试」。背景：我在另一台机器上开发了一个
Windows 微信自动化项目（群相 / Persona Morph），外加一个桌面启动器和一个知识包插件。
我这台机器的环境你**不能当作标准**，所以要请你在这台机器上实测，并把结果发回给我。

【第一步：先别动手，先跑环境指纹】
在包根目录执行：py -3 scripts/collect_report.py
它会生成 报告\检验报告-<时间戳>.txt 和 .json —— 这是"这台机器长什么样"的自包含指纹
（系统 / DPI / 分辨率 / 显示器 / 微信版本 / UI 类名 / 窗口几何 / 依赖 / 输入档位 / 会话头可读性）。
把这个文件原样发回给我，我看完再决定后面怎么测。

【第二步：按清单测（我会在收到指纹后给你具体顺序）】
顺序见包里的 docs\跨机测试交接包.md §2；每条都要**留证据**，不要"我点了应该好了"。

【这台机器的纪律（请严格遵守）】
① **不许动用户的鼠标、不许抢前台**：任何操作前后用 GetCursorPos / GetForegroundWindow 比对并写进报告；
   确需真实点击时，必须在脚本头部写明"这是阳性对照"，用完恢复光标。
② **不许往微信发任何对外可见的东西**：测试消息只能发给「文件传输助手」或你自己的小号；
   不许点赞/评论/发表朋友圈（这些是真实社交动作，要用户点头）。
③ **报告里不许带个人信息**：不要写用户名、邮箱、手机号、真实聊天内容（报告工具已内置脱敏，别自己加）。
④ **未自测不得声称完成**：凡是"能/不能"的结论都要有可复核的证据（DB 回读 / 窗口枚举 / 像素差 + 对照）。
⑤ **失败要留现场**：截图 + 日志片段 + 当时的窗口状态，放进 报告\fail\<时间戳>_<原因>\。
⑥ 拿不准的东西**直接说不确定**，不要猜；猜错的结论比"不确定"更贵。

【回传什么】见 §3：报告文件 + 结论.md（OK / FAIL / 跳过(污染) 三栏分开）+ 失败现场目录。
【注意】报告里如果出现"跳过(污染)"，那是**用户正在操作电脑导致的环境干扰**，不是功能缺陷，
        请按 §3 的格式单独计一栏，不要混进 FAIL。
```

## 2. 要测什么（分阶段，每项都有判据）

### 阶段 0 · 环境指纹（先做，5 分钟）
- 跑 `py -3 scripts/collect_report.py` → 发回 `.txt` + `.json`。
- **判据**：报告能生成、无异常（工具设计成"永不崩"，某节失败要在报告里写明"这一节失败/不适用"）。
- **我要从里面看**：那台机器是 Win10 还是 Win11 · 缩放比 · 微信版本与主窗类名（**这决定它是不是"旧版 UI"**）。

### 阶段 1 · 只读兼容性（不动微信、不需要登录）
按 `_scratch/兼容性矩阵.md` 的 **13 条轴**逐条跑，每条记"取值 × 可测否 × 结果"：
A 微信版本/UI 代 · B 主题/字体/语言 · C DPI 缩放 · D 分辨率/窗口尺寸 · E 多显示器混合 DPI ·
F 系统叠加层（输入法候选/遮挡）· G 权限级别（微信是否以管理员运行）· H 会话状态 ·
I 输入内容 · J RDP/VM · K 多开多账号（其余按矩阵表逐条）。
- **判据**：每条给出"本机能不能测 / 测出来是什么 / 与我这台是否一致"。

### 阶段 2 · 产品链路（需要微信登录，建议用小号）
1. **DSH 启动器**：能否装上 → 守护启动 → 检测修复 → 快照回滚（各截一张图）。
2. **知识包插件**：装上后侧栏「逻辑知识网络」在不在、E 控制台能不能开、记忆工具能不能用。
3. **群相本体**：控制台能不能开（回环 127.0.0.1 + 口令）→ 能不能读消息库 → **投递发文字**（判据＝DB 回读）→
   **真语音条**（判据＝DB 回读 `type=语音`；录音源需要把微信输入设备指到虚拟声卡）。
4. **红线自检**：全程光标未动、前台未变（这两条要出现在报告里）。

### 阶段 3 · 异常与边界（可选，按兴趣）
最小化时能否发送 · 窗口被遮挡时能否发送 · 多显示器下坐标是否正确 · 微信版本不匹配时的提示是否清晰。

## 3. 要回传什么（格式要求）

1. `报告\检验报告-<时间戳>.txt` 与 `.json`（原样，别改动）；
2. 一份 `结论.md`，**三栏分开**：

| 项 | 结果 | 证据（文件/行号/数字） | 备注 |
|---|---|---|---|
| 阶段 0 环境指纹 | OK / FAIL / 跳过(污染) | 报告第 N 节 | — |
| A 微信版本/UI 代 | … | 主窗类名 = … | 与开发机是否一致 |
| … | | | |

3. 失败项：`报告\fail\<时间戳>_<原因>\` 目录（截图 + 日志 + 当时的窗口状态）；
4. 一句话总结：**这台机器上"能用 / 不能用"分别是哪些**（宁少勿虚）。

**三类必须分开计数**：`OK` / `FAIL` / `跳过(污染)`。
理由：用户可能就在同一台机器上操作（实测过"预检相似度 1.000、发送瞬间变 0.755"这种事），
环境干扰**不是**功能失败，混在一起会把结论带偏。

## 4. 我们这边的前置（发之前要准备的）

- **测试包**：`wx-agent` 在线包（版本库里的代码，约 3.7 MB / 108 文件）+ 启动器发布包；
  两者都已按"在线包"口径打包（**不再有离线包**——模型运行本来就要联网）。
- **虚拟声卡**（真语音条需要）：随包带上 `VB-CABLE` 驱动包与一页安装说明；
  **安装前必须让用户知道**这是要动系统驱动的（我们这边原则：能静默就静默，但装驱动要用户点一次）。
- **开场白**：§1 那段（可直接粘贴）。
- **回收位置**：那台机器跑完把 `报告\` 整个目录发回来即可（发到我的微信会话或网盘）。
