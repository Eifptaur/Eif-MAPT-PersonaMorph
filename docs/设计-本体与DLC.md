# 设计：本体 + DLC（增量更新 + 公告系统）

> 用户口径（2026-09-14 原话）：「我们的 3 个项目都写成类似**本体加 DLC** 的形式，以后更新可以**直接增量更新**，不用换整包，可以吗，更新了，用**公告系统**告诉用户，看他要不要更。」
> 结论：**可以**，而且启动器那边已经跑通了一半（`[520]` 增量补丁 + sha256 校验 + 备份回滚）。这份文档把"本体 / DLC / 清单 / 增量 / 公告 / 回滚"六件定下来，三个项目照同一套契约走。

## 一、三个概念（先对齐）

| 概念 | 是什么 | 谁负责 |
|---|---|---|
| **本体**（base） | 最小可运行体：主程序 + 运行时 + 启动链。**变化慢、体积大** | 各自项目 |
| **DLC**（包） | 功能包：技能包 / 能力包 / 界面包 / 配置包。**可装可卸可停用**，带清单与哈希 | 各自项目 |
| **更新清单**（manifest） | 一个 JSON：本体版本、每个 DLC 的版本/哈希/依赖/兼容区间、**公告文案**、是否强制 | 发布端（现在＝本机生成的清单文件 / 将来＝你的服务器） |

## 二、三个项目的映射与现状

| 项目 | 本体 | DLC | 现状 | 差距 |
|---|---|---|---|---|
| **Agent启动器** | `Agent启动器.exe` + 5 个 DLL + `ops-http.js` + 运行期 JSON | 插件（`dsh plugin` 那批）＋ 技能包 ＋ 主题/素材包 | ✅ 已有 `[520]` 增量（只下变更文件，`LauncherUpdater --patch`，sha256 校验 + 备份 + 回滚）· ✅ 有更新检查（关于页"检测更新/开始更新"） | ⚠️ **没有公告字段**（现在的 Notice 是界面提示函数，不是更新公告）；DLC 的"停用/一键摘除"还没有统一入口 |
| **群相灵 Persona Morph** | 在线包（~1.85MB / 108 文件）＝Python 代码 + `一键启动.exe` + `launcher-src` | 技能包（`~/.dsh/skills`）· 控制台面板 · 媒体/语音能力 · 人设与名单（可选上云） | ⚠️ 目前**整包替换**（换 zip） | 需要：①本体/DLC 边界（**驱动微信那层锁本体**：`wechatauto-replica`/UIA/ctypes 不许 DLC 化）②增量包（按文件哈希 diff）③本地清单与版本记录 |
| **插件包（Eif-MAPT-skills）** | DSH 本体（`dsh` CLI） | 技能包本身 | ✅ 天然是 npm 包：可单装、可卸、可指定版本（`dsh plugin add file:…tgz`） | 只差"公告 + 一键更新"（DSH 插件列表已有启停） |

## 三、清单格式（三项目共用一份契约）

```json
{
  "product": "persona-morph",
  "base": { "version": "0.9.0", "sha256": "…", "url": "…", "size": 1900000 },
  "dlc": [
    { "id": "skills.core", "name": "技能包·核心", "version": "0.5.25",
      "requiresBase": ">=0.9.0 <1.0.0", "deps": ["skills.common"],
      "sha256": "…", "url": "…", "size": 268000, "enabledByDefault": true },
    { "id": "panel.console", "name": "控制台面板", "version": "0.1.4",
      "requiresBase": ">=0.9.0", "sha256": "…", "url": "…" }
  ],
  "announce": {
    "id": "2026-09-14-skills-0.5.25",
    "level": "normal",              // normal | important | security
    "title": "技能包更新：删掉解释性括号 + 侧栏入口撤下",
    "body": "本次只改了描述与界面；不影响已配置的功能。",
    "forceBase": false,             // 本体必须更（安全补丁）时为 true
    "minBase": "0.9.0"
  },
  "updatedAt": 1789315193574
}
```

**硬规矩**：①清单里的每个包都带 **sha256**（没有哈希的更新链一律不认，MAA 的反面教材）；②`requiresBase` 不满足**不装**（只提示），不静默降级；③公告**只读**、不携带可执行内容。

## 四、增量怎么算（三项目统一做法）

1. **发布端**：拿新旧两版目录做逐文件 `sha256` diff ⇒ 生成 `patch{from, base, plan}`（plan = 新增/替换/删除的文件 + 哈希 + 大小）。
2. **客户端**：拉清单 → 比对本地版本 → **只下 plan 里那几件** → 逐件校验 sha256 → 落到暂存目录 → 换入 → 组合校验。
3. **失败即回滚**：换入前先快照当前目录（启动器已有 `rollbacks\<profile>\<stamp>` 机制），任一步失败回滚并留日志。
4. **本体更新**：同样走 plan；`forceBase=true` 时不做增量、整包替换（安全优先）。

**启动器**已实现 1–3（判据 `check-patch520` 37/0，含内嵌端到端 12/0）；**群相灵**与**插件包**照抄这套流程（群相灵按文件 diff，插件包直接吃 tgz 的版本号）。

## 五、公告系统（"看他要不要更"）

- **拉取**：本体启动时（或每 N 小时）拉一次清单；**离线/拉不到 ⇒ 静默跳过**，不弹任何东西。
- **展示**：控制台 / 启动器"关于"页出现一条公告条（自绘、无 emoji）：标题 + 正文 + `[立即更新] [稍后] [不再提醒这个版本]`。
- **选择权在用户**：默认**不自动更新**；`security` 级公告才建议立即更（仍不强制，除非 `forceBase`）。
- **纪律**：公告只在**本机 UI**出现；**绝不往微信侧发**（这条与风险闸门同一口径）。
- **实测要求**：公告条要有"拉不到/清单坏了/版本不匹配"三态截图；更新动作要有"下到一半断网"的回滚演练。

## 七、边界（写清楚，免得以后返工）

1. **驱动层不许 DLC 化**：群相灵里碰微信进程/内存/写 `Weixin.dll` 的那层**必须锁在本体**（开源切分与法律口径都在这层）。
2. **DLC 不带代码执行权限升级**：DLC 只能是"我们签过的包"（sha256 + 来源清单）；第三方 DLC 一律显式 opt-in + 可停用。
3. **不做静默更新**：任何包换入都必须经过用户可见的公告与选择（`forceBase` 例外，且要写明理由）。
